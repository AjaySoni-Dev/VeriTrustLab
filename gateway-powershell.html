01 · Evidence boundary

What the demo proves

Direct observation matters.Raw email headers can be forged or reconstructed. The receiver records the SMTP client IP, HELO, envelope sender, receipt time, and receiver identity at a configured trust boundary. VeriTrust keeps these facts separate from unverified Received: claims.
Claim boundaryThis is infrastructure provenance and approximate infrastructure location, not exact attacker or person geolocation.

02 · Prepare once

Prerequisites

Both laptops

Windows PowerShell 5.1+ and Tailscale. Sign both machines into the same or shared tailnet before the presentation.

Receiver only

Node.js 24, a dedicated VeriTrust API key scoped to gateway:scan, and VERITRUST_EMAIL_RECEIVER_SECRET of at least 32 bytes. The deployed API should trust VERITRUST_TRUSTED_AUTHSERV_IDS=veritrust-smtp-gateway.

Demo package

Use the complete ZIP above. It contains the sender, receiver, launchers, validator, and the exact matching mail-gateway runtime. No GitHub source download is required.

03 · Receiver laptop

Start the trusted receiver

Receiver laptopLaunch from the extracted package
Set-Location C:\VeriTrust-Demo
$env:VERITRUST_API_BASE_URL = "https://www.veritrustlab.in"
.\Run-VeriTrust-Receiver.cmd

On first use, enter the receiver-only API key and receiver secret. They are DPAPI-protected on that Windows user profile. The console prints a short-lived pairing code for the sender. Never copy the VeriTrust API key or receiver secret to the sender laptop.

04 · Sender laptop

Pair the sender

Sender laptopLaunch and paste the receiver pairing code
Set-Location C:\VeriTrust-Demo
.\Run-VeriTrust-Sender.cmd

The pairing code contains only the temporary SMTP endpoint and ephemeral SMTP credential. A new receiver run generates a new password.

05 · Live transaction

Send an original .eml

Sender consoleSubmit a controlled EML fixture
/send C:\VeriTrust-Demo\fixtures\suspicious.eml
Expected behaviorThe sender shows the SMTP outcome while the receiver shows direct boundary facts, VeriTrust analysis progress, and the final allow/reject/defer decision. A block returns SMTP 550; an analysis/API failure defers rather than silently treating the message as safe.

06 · Recovery

Three checks if the demo does not connect

Peer unavailable

Confirm both machines are online in Tailscale and the sender can see the receiver's 100.x address.

TCP 2525 blocked

Restart the receiver elevated so the restricted Windows Firewall rule can be repaired. Do not expose TCP 2525 publicly.

Analysis deferred

Verify the deployment origin, the receiver-only gateway:scan key, receiver secret, and Vercel runtime configuration. Treat provider/API failure as a safe defer condition.

Security boundaryReceiver laptop: VeriTrust API key + receiver secret. Sender laptop: only the short-lived SMTP pairing credential. Keep the receiver port restricted to private/Tailscale peers.
